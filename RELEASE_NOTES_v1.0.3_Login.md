## 🌟 Ключевые изменения и результаты задачи

### 🔄 Архитектура сквозной авторизации: Frontend <-> Backend <-> База данных (10 шагов)

Полностью реализован и протестирован цикл взаимодействия по всем 10 шагам спецификации:

1. **Шаг 1. Открытие страницы и вызов авторизации:**  
   Пользователь открывает `http://localhost:3000/index.html` и нажимает кнопку **«Войти»** в навигации или на карточке резидента.
2. **Шаг 2. Модальное окно ввода:**  
   Появляется защищенное окно авторизации с полями `Email` и `Пароль` (с функцией отображения/скрытия пароля через иконку глаза) и карточками быстрого входа для резидентов.
3. **Шаг 3. Отправка формы:**  
   Пользователь нажимает кнопку **«Войти в кабинет»**.
4. **Шаг 4. Валидация на стороне Frontend:**  
   JavaScript проверяет:
   - Заполненность полей email и пароля;
   - Корректность формата email регулярным выражением (`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`);
   - Минимальную длину пароля (не менее 6 символов).
   При нарушении фокус переносится на поле ошибки и выводится рубиновое предупреждение без лишних сетевых запросов.
5. **Шаг 5. Сетевой HTTP-запрос к Backend:**  
   Frontend выполняет асинхронный `POST /api/auth/login` с заголовком `Content-Type: application/json` и телом `{"email": "...", "password": "..."}`.
6. **Шаг 6. Поиск пользователя в базе данных (Backend -> DB):**  
   FastAPI через SQLAlchemy и сессию базы данных `resonance_club.db` выполняет поиск:  
   `user = session.query(User).filter(User.email.ilike(email)).first()`.  
   Если пользователь с таким email отсутствует, сервер возвращает статус `404 Not Found` с телом `{"success": false, "error": "user_not_found", "message": "Пользователь с указанным email не зарегистрирован в клубе."}`.
7. **Шаг 7. Проверка криптографического хеша пароля:**  
   Если пользователь найден, бэкенд проверяет совпадение через `user.check_password(password)` (алгоритм `PBKDF2-HMAC-SHA256` с уникальной солью).  
   - При несовпадении пароля сервер возвращает `401 Unauthorized` с ошибкой `invalid_password`.  
   - При попытке входа учетной записью **Superadmin** (`superadmin@resonance.club`), бэкенд возвращает статус `403 Forbidden` с системным уведомлением о необходимости перехода в защищенный пульт `/admin`.
8. **Шаг 8. Создание сессии и выпуск токена авторизации:**  
   При успешной проверке бэкенд:
   - Генерирует криптографически подписанный Bearer-токен `access_token` (`HMAC-SHA256` с payload `sub`, `email`, `role`, `exp`);
   - Устанавливает безопасную HTTP-only куку `resonance_session`;
   - Возвращает JSON с токеном, временем жизни и полным объектом профиля пользователя.
9. **Шаг 9. Доступ к личному кабинету и верификация:**  
   Frontend сохраняет токен (`resonance_token`) и данные профиля в `localStorage`, анимирует кнопку подтверждения и перенаправляет пользователя на `profile.html`.  
   Страница `profile.html` при загрузке отправляет запрос `GET /api/auth/me` с заголовком `Authorization: Bearer <token>`, сверяет подлинность сессии с базой данных и отображает имя, возраст, профессию, статус резидента и VIP-код.
10. **Шаг 10. Отображение ошибок:**  
    При любых некорректных данных (неверный логин, пароль, ограничение суперадмина) в модальном окне выводится информативное сообщение об ошибке, а форма остается активной для повторного ввода.

## 🔌 Эндпоинты серверного API (`app_admin.py`)

* **`POST /api/auth/login`**:
  * Тело: `{"email": "...", "password": "..."}`
  * Ответ 200: `{ "success": true, "token_type": "Bearer", "access_token": "...", "user": { ... } }`
  * Ответ 404: `{ "success": false, "error": "user_not_found", "message": "..." }`
  * Ответ 401: `{ "success": false, "error": "invalid_password", "message": "..." }`
  * Ответ 403: `{ "success": false, "error": "superadmin_restricted", "message": "...", "admin_url": "/admin" }`
* **`GET /api/auth/me`**:
  * Заголовок: `Authorization: Bearer <access_token>` или кука `resonance_session`
  * Проверяет токен и возвращает актуальные данные пользователя из БД.
* **`POST /api/auth/logout`**:
  * Завершает сессию и очищает сессионные куки.
* **`GET /api/auth/residents`**:
  * Возвращает список всех резидентов (за исключением superadmin) для динамического построения интерфейса.
